# Ma ZP — consignes de travail

- `index.html` charge `js/app.min.js`, construit à partir de `js/` par `node outils/construire.mjs` (esbuild).
  **Après toute modification d'un fichier de `js/`, relancer la construction et committer `js/app.min.js` avec le reste**, sinon les joueurs ne voient pas le changement. `node test/construit.test.mjs` vérifie que le fichier est à jour. Filet de sécurité : l'action GitHub `.github/workflows/construire.yml` le reconstruit aussi automatiquement à chaque push sur main qui touche `js/`.
- Parcours complet en navigateur : servir le dossier (ex. `http-server -p 8765 -c-1 .`) puis `node test/browser.mjs <dossier-captures> "http://127.0.0.1:8765/?demo"`.
- **Toute modification de `js/engine/` ou `js/quests/` (règles, équilibrage, génération) : monter `APP_VERSION` dans `js/engine/constants.js`**, puis `node test/version-moteur.test.mjs --maj`. Sinon un appareil resté sur l'ancienne version (cache) peut calculer le tour de 20:00 avec les anciennes règles. `node test/version-moteur.test.mjs` échoue tant que ce n'est pas fait.
- **Mini-jeu Bitonal (`minijeux/bitonal.html`) : avant tout push qui le touche, `node test/bitonal-collisions.test.mjs` doit passer** (0 problème). Il vérifie, sur des centaines d'accrochages, que l'obstacle percuté était réellement dessiné juste avant le choc et visible à l'écran. L'action GitHub « Tests des mini-jeux » le relance à chaque push. Ne jamais annoncer « corrigé » sur un bug de jeu sans un test qui échoue sur l'ancienne version et passe sur la nouvelle.
- **Règle générale des mini-jeux : ce qui peut toucher le joueur doit être ce qui est dessiné.** Collision et dessin doivent utiliser les mêmes conditions (mêmes bornes, même ordre d'affichage) ; un test doit observer le rendu réel du jeu (accroche de débogage), pas recalculer de son côté ce qui « devrait » être visible.
